# 设计方案

版本：v1（2026-09-23 重启）
状态：待实现

---

## 1. 我们在解决什么问题

一个 5-6 岁的小朋友想玩桌游/卡牌，但：

- 实体桌游需要大人全程陪着讲规则、发牌、当对手
- 市面上的儿童游戏 App 普遍有广告、内购、无节制的激励循环
- 孩子还不太认字，大部分游戏的引导对她/他是无效的

所以做一个自己可控的游戏合集：**孩子能独立打开、独立看懂、独立玩完一局**，大人不需要在旁边解释。

### 成功是什么样

孩子主动要求"我要玩 iPad 上那个游戏"，且玩的过程中不喊大人。

**不是**功能清单做完，**不是**代码架构漂亮。

---

## 2. 用户是谁：5-6 岁的能力边界

这一节是所有设计决策的依据，不是背景介绍。

| 能力 | 现状 | 对设计的约束 |
|---|---|---|
| 阅读 | 认字极少，可能认识自己名字和少量常见字 | 界面不能依赖文字传达信息；文字一律配语音 |
| 数字 | 能数 1-10，认识骰子点数 | 用圆点/图形表示数量优于阿拉伯数字；走格子时逐格报数正好是练习 |
| 颜色形状 | 熟练 | 颜色和图形是主要的信息载体 |
| 精细动作 | 点按可靠，拖拽不精确 | 核心操作必须能靠点按完成；拖拽只能是可选的增强 |
| 注意力 | 10-15 分钟 | 单局控制在 3-8 分钟；必须可随时中断并恢复 |
| 输赢承受 | 弱，输了容易崩溃或拒绝再玩 | 高运气成分；AI 会犯错；不做失败叙事 |
| 轮流意识 | 正在形成中 | "轮到谁"必须极其明显；这是本项目附带的教育价值 |

### 由此得出的五条设计原则

1. **零阅读依赖** —— 把界面上所有文字盖掉，仍然能玩。
2. **立即反馈** —— 每次触摸在 100ms 内给出视觉 + 听觉回应。孩子需要确认"我点到了"。
3. **永不卡死** —— 任何状态都有一个高亮元素在说"点我"。没有"孩子不知道现在该干什么"的时刻。
4. **可中断** —— 随时退出，状态自动存；回来能继续。孩子的游戏会被吃饭、洗澡打断。
5. **不制造压力** —— 无倒计时、无排行榜、无连败提示、无"失败"字样。

## 3. 信息架构

```
首页（游戏选择）
  └── 游戏内
        └── 结算页 ──> 再来一次 / 换个游戏
家长入口（隐藏）
```

**首页**：大卡片网格，每张卡片一个游戏。卡片 = 大图标 + 游戏名（配点击朗读）。没有列表、
没有分类 Tab、没有搜索。孩子第一眼看到的就是游戏本身。

**游戏内**：棋盘/牌桌占绝大部分屏幕；当前回合的玩家头像明显放大发光；一个提示按钮（点了会
高亮可行动作）。退出按钮做小、放角落，避免误触。

**结算页**：庆祝动画 + 两个大按钮（再来一次 / 换个游戏）。赢和"没赢"用同样欢快的基调，
差别只在庆祝程度，不出现失败文案。

**家长入口**：首页右上角一个**很淡的普通按钮**，点一下就进。

> 原本做成长按 3 秒防误入，2026-09-23 iPad 实测后改掉：按住时手指正好盖住进度环，
> 反馈等于不存在；而 5 岁的孩子已经能判断"这个不是我要点的"。**不要用交互难度
> 代替信任**——图标做淡、不吸引注意就够了。

里面放：

- 各游戏难度（含 **UNO 牌组等级 L1~L4**，见 5.3）
- **新手辅助开关**（可出牌高亮，默认开）
- 音量、游戏时长提醒、清空记录

### 明确不做

登录、注册、个人资料编辑、大厅、房间列表、好友、排行榜、成就。

旧版本全做了，这是重启的主要原因——孩子打开 iPad 后应该直接看到游戏。玩家身份在第一阶段
只是本地存的一个头像选择（从 6-8 个卡通头像里点一个）。

## 4. 技术方案

### 4.1 为什么是 Web 优先

选 Vue 3 + TypeScript + Vite，产出纯前端 PWA，iPad Safari 打开后"添加到主屏幕"，
全屏、无浏览器 UI、离线可玩——对孩子来说它就是一个 App。

| 方案 | 为什么没选 |
|---|---|
| uni-app 一套代码两端 | 早期全部价值在"孩子玩得爽"，需要快速迭代动画和手感，而小程序的渲染/手势限制会反复受限；微信联机是长期目标，到时加壳 |
| 原生 iOS App | 装到 iPad 需要上架或开发者证书；且无法借微信关系链，与长期目标冲突 |

选 **Vue 而非 React** 的理由：将来若真要回到微信小程序，uni-app 是 Vue 生态，规则引擎和
组件可大比例复用；且旧版代码是 Vue，规则逻辑可作参考。

### 4.2 核心抽象：游戏模块

加一个新游戏不应该改动任何核心代码。每个游戏是一个自包含模块：

```ts
interface GameModule<S, A> {
  meta: GameMeta                                  // 名称、图标、人数、单局时长、难度档
  createInitialState(config: GameConfig): S        // 开局
  applyAction(state: S, action: A): S             // 纯函数：唯一的状态变更入口
  getLegalActions(state: S, playerId: string): A[] // 供 UI 高亮和 AI 选择
  isFinished(state: S): boolean
  getWinner(state: S): string | null
  chooseAiAction(state: S, playerId: string, difficulty: Difficulty): A
  component: Component                             // 游戏界面
}
```

**`applyAction` 必须是纯函数**（不可变、不碰 DOM、不读全局）。这一条同时支撑三件事：

- 规则可以单元测试（旧版 UNO 的 bug 主要来自规则和 UI 纠缠在一起，无法测）
- AI 可以"试算"几种走法再决定
- **将来联机时服务端能用同一份规则做权威校验**，这是联机的前提

游戏注册表 `src/core/game-registry.ts` 汇总所有模块，首页直接渲染注册表。

### 4.3 AI 设计：会犯错的对手

每个游戏实现 `chooseAiAction`，纯函数。

**难度不通过搜索深度调节，而是通过"故意选次优解的概率"**：

| 难度 | 次优概率 | 适用 |
|---|---|---|
| 简单 | 60% | 默认。孩子大概率能赢 |
| 普通 | 30% | 孩子玩熟之后 |
| 认真 | 5% | 大人自己玩 |

AI 还需要"人味"：头像、表情动画、预写的语音台词（"我要出红色啦！""哎呀我忘了"）。

**5-6 岁孩子感知到的陪伴感主要来自语音和表情，不来自棋力。** 所以不接大模型——联网延迟
几秒对这个年龄的孩子是不可接受的，而且要额外处理儿童内容安全。接 Claude API 做"会真的
聊天的 AI 玩家"是阶段 5 以后的可选增强，不是现在的需求。

### 4.4 音频

所有语音**预先用 TTS 生成成音频文件**存进 `src/assets/audio/`，不做运行时 TTS。
理由：零延迟、离线可用、音色可控。

音效分三类：操作反馈（点击/翻牌/掷骰）、状态提示（轮到你了/可以出这张）、情绪
（庆祝/惊讶/鼓励）。

> iOS 限制：首次播放音频必须由用户触摸触发。首页需要一次"点击开始"的交互来解锁音频上下文。

### 4.5 存储

localStorage 即可，无后端：选定的头像、难度设置、每个游戏的进度与已玩次数。

### 4.6 长期：微信联机的路（现在不做，但不堵死）

三个首批游戏都是**回合制、状态体积小**，所以联机不需要实时帧同步，只需要"动作广播 +
服务端权威校验"。做到 4.2 的纯函数规则引擎，联机就只剩传输层的工作。

到时两条路线（届时再选）：uni-app 壳复用规则引擎，或小程序 webview 嵌 H5。

**合规提醒**：公开发布"小游戏"类目涉及未成年人防沉迷与实名认证等要求。**只给自己孩子玩、
用本地或体验版，不涉及这些。** 这也是把公开发布排到最后的原因之一。

## 5. 首批三个游戏的规格

选择标准：规则简单、运气成分高、单局短、复用同一套回合制框架。

### 5.1 翻牌配对（记忆棋）—— 第一个做

最容易做出"好玩"的手感，且零阅读需求。

- **难度分级用图案数量，不用时间压力**：4 对（2×4）/ 6 对（3×4）/ 8 对（4×4）
- **图案**：动物、水果，颜色区分度高，避免形状相似的组合
- **模式**：单人（翻完即通关，记步数但不呈现为"失败"）/ 和 AI 轮流翻（配对成功得牌，多者胜）
- **AI 降智方式**：记忆窗口有限——只记得最近翻开过的 N 张牌，N 随难度变化，所以 AI 会"忘记"
- 翻牌动画 + 配对成功的庆祝反馈是这个游戏的核心体验，值得多花时间打磨

### 5.2 蛇梯棋 —— 验证多人回合制

比飞行棋规则更简单（飞行棋有起飞、撞子、叠子等规则），先做蛇梯棋。

- 1-50 的路径，遇梯子上升、遇滑梯下降，先到终点胜
- **掷骰子**：大按钮 + 骰子动画 + 音效，点数用**圆点**显示（不认字也能懂）
- **走格子**：棋子逐格跳动，每格一个计数音效并报数——顺便就是数数练习
- 2-4 人，AI 对手就是自动掷骰（零策略），可同时配多个 AI
- **儿童友好关键点**：滑梯下降要做成幽默动画（"哇——"滑下去），而不是惩罚感
- **两处刻意不按经典规则**：① 走过头也算到终点，不要求正好掷中（经典规则要往回退，
  只是徒增挫败）；② 掷到 6 不额外加一轮（少一条要解释的规则，局也更短）
- 全程没有任何选择，所以**难度设置对本游戏无效**

> ⚠️ **这条当初判断错了。** 原文写的是"零选择正是它适合 5 岁孩子的原因：纯运气，
> 没有人会玩得不好"。2026-09-24 用户实测反馈："感觉没有什么参与感，小朋友玩的
> 类似游戏都会有一些操作和动作，这个只有扔骰子"。
>
> **正确的目标不是"零选择"，而是"选择很容易、代价很小"。** 零选择确实避免了挫败，
> 但同时消灭了参与感 —— 孩子要的是"我做了什么"，不是"我看着什么发生"。
> 这个游戏因此待替换，候选方案见 ROADMAP 阶段 4。

#### 让棋盘看得懂（2026-09-23 第一版实测后重做）

第一版是白底方格加两根细线，用户（人生第一次玩蛇梯棋，正好是最好的新手样本）的
反馈是"看不出这是一条路、很单调、梯子也不明显、动物太小"。改法：

- **相邻格子深浅交替**，两色要拉开差距。这是"这是一条路"最直接的线索，
  第一版两色太接近，等于一张白纸
- **折返处画向上的箭头**。走到行尾拐到上一行是蛇形棋盘最难懂的地方。
  （试过画一条贯穿 50 格的折线，实测像一团方框、更乱，已去掉）
- **梯子画成真的梯子**（两根边梁 + 横档），**滑梯画成弯的宽带子**——
  形状不同才能一眼区分，细线做不到
- **格子之间留大间隙**，露出底下的天空/草地背景，棋盘才像个场景而不是表格
- **棋子大小跟着格子走**（容器查询单位）而不是跟着屏幕。同格多个棋子排成 2×2
  并缩小——开局四人全挤在 1 号格是最坏情况，也是第一眼看到的画面
- **落格后原地转一圈**，标记"我停在这儿了"

#### 骰子和轮次

- 骰子是 **CSS 3D 立方体**，多转几圈再停到目标面。第一版是平面切换点数图案，
  反馈是"不好理解"——平面切换看不出"在掷"，只看出"数字变了"
- 骰子有自己的一块面板可以上下蹦，不是挤在角落的一个按钮
- **轮次固定显示在右侧栏**，不混在棋盘里：当前玩家整块卡片亮起 + 箭头指着
- **有人到终点后先在棋盘上庆祝 2.4 秒**（赢家棋子蹦 + 礼花）再弹结算页。
  第一版一到终点立刻弹窗，反馈是"没注意到就切走了"

### 5.2b 四子棋 —— 替掉蛇梯棋（2026-09-24）

选它的理由正好对着蛇梯棋的病根：**有真正的选择（往哪一列丢），但规则一句话讲完**。
"选择很容易、代价很小"，这才是我们要的，不是"零选择"。

- 7 列 × 6 行，连成四个赢（横竖斜都算）
- **整列都是点击区**，孩子不用瞄准某一格
- 棋子是**彩色圆片 + 头像**：颜色负责"一眼看出连成一线"，头像负责"这是谁"
- 落子有掉落动画，连成的四个会亮起来跳动，先亮 2 秒再弹结算
- 两种模式：和电脑玩 / 两个人轮流用一台（和翻牌配对一致）

**"连成四个就赢"要画出来，不能靠讲**（2026-09-24 用户提出）。规则一句话讲得完，
但孩子不认字，一句话也讲不了。所以做了 `WinHint.vue`：横、竖、斜各一张小棋盘，
四个子依次亮起来再连成一条线，循环播放。
- 进游戏的选人页上**常驻**一份 —— 不用点任何东西就看见了
- 第一次开局自动弹一次浮层 + 语音"连成四个就赢啦，横的、竖的、斜的都算"，讲完自动收
- 之后 HUD 右上角有个 `?`，随时再看。一次开 app 只自动弹一次，玩第二局不再挡着
- **三个方向都要画**：只画横的，孩子就只会去凑横的（首页图标就只画了横的）

AI 只有三条朴素规则，不做搜索：能赢就赢 → 对手要赢就堵 → 否则往中间放。
**这个游戏有真技巧，所以降智特别重要**（简单档 60% 概率乱下）—— 和 UNO 不同，
这里认真档对简单档确实赢得多，有测试守着。

> **棋子一度完全看不见**（2026-09-24 用户实测）。棋盘格子写了 `padding: 7%` 想给棋子
> 留点边，但格子是绝对定位的，**百分比 padding 按包含块算** —— 7% 是按整块棋盘 685px
> 算的 = 48px，把 98px 的格子吃到只剩 2px，棋子和头像跟着塌成一个点。
> 改成给棋子 `position:absolute; inset:8%`（inset 才按格子自己算）。
> 教训同上一条 `container-type`：**尺寸对不上时先量 DOM 的 computed 值，别猜**。

### 5.3 UNO（完整规则 + 可配置牌组）—— 规则最复杂，排最后

**做法变更（2026-09-23 用户决定）**：不做"简化版"，而是**一次实现完整规则，然后用"牌组里
放哪些牌"来调难度**。

这比砍规则更好，原因是：难度阶梯本身就是教学路径。每解锁一种功能牌，就是教孩子一个新概念，
而且孩子已经掌握的部分完全不变——不需要重新适应。

#### 难度阶梯（家长端设置，也可随孩子进度手动解锁）

| 等级 | 牌组 | 孩子要学会的新概念 |
|---|---|---|
| L1 | 数字牌 0-9 四色 | 颜色匹配、数字匹配。纯粹的"找一样的" |
| L2 | + 跳过 | 我出的牌会影响别人（第一次有"策略"） |
| L3 | + 反转、+2 | 顺序会变；我可以让别人抽牌 |
| L4 | + 万能牌、万能 +4 | 我可以指定颜色（最抽象的一步） |

技术上这是**一个配置对象**，规则引擎实现全部牌型，发牌时按启用的牌型组牌。
不是四套代码，也不是 feature flag——`enabledCardTypes` 就是游戏配置的一部分。

> **反转的一个注意点**：两人局里反转的效果等同于跳过（轮次转回自己），孩子感知不到区别。
> 反转的教学价值只在 **3 人以上**（自己 + 2 个 AI）才体现出来。所以 L3 默认配 2 个 AI。

#### 规则取舍

| 做 | 不做 | 原因 |
|---|---|---|
| 完整的出牌/抽牌/功能牌规则 | **质疑（挑战万能 +4）** | 用户明确不做。这条规则需要推理别人手里有什么，远超这个年龄 |
| 剩一张牌时**自动**触发喊 UNO 音效 | 喊 UNO 失败的举报与罚抽 | 不让孩子因为"忘记做一个动作"被惩罚 |
| 官方规则：+2/+4 直接生效 | 累计叠加加牌（house rule） | 叠加不是官方规则，且会造成一次抽 6-8 张的挫败 |

### 5.4 面对面一起玩：先做"一台 iPad 轮流"（2026-09-24）

用户问联网多人（房间号、免登录）的成本。结论：

- **钱不是问题**：Cloudflare Durable Objects 已在免费版，WebSocket 空闲休眠不计时长
- **工作量是问题**：比任何单个游戏都大 2-3 倍，且难点不在通信，在**断线重连**
  （5 岁孩子的 iPad 会锁屏、会被切走、人会跑开）和"等待别人"的状态设计
- **但面对面根本不需要联网**：同一台 iPad 推来推去，和真的桌游一样

所以先做 `duo` 模式（两个人轮流用一台）。翻牌配对零额外设计（牌都是公开的），
已经做好；UNO 需要藏手牌、要加交接屏，往后放。

**换人提示**：两个人轮流时没有 AI 的停顿当信号，所以换人时把新玩家的头像
在屏幕中央放大弹一下。这是这个模式唯一的新交互。

**真人和电脑靠形象区分**：真人一律是小动物（🐻🐰🐱…），电脑一律是机器人
和外星人（🤖👾👽）。原来电脑也用小动物、只在选择页加了个小角标，
用户实测反馈"有一些些理解成本" —— 对不认字的孩子，**用形象本身区分**
比加标记可靠得多。也没用 1P/2P 这类写法：那要求认字，而且是成人游戏圈的惯例。

联机的真正触发条件不变（见 ROADMAP 阶段 5）：先看她玩 `duo` 玩不玩得开心，
开始说"我也想自己拿一个"才是做联机的信号。

#### 让人看出这是 UNO（2026-09-23 第一版实测后重做）

第一版的牌就是纯色方块加一个数字，用户反馈：**"懂得规则的人也很难理解这是在打 UNO"**，
而且看不到对手手牌数、看不出摸牌堆、出不了的牌连颜色都看不清。改法：

- **牌面照着真牌画**：彩色牌身 + 中间一个斜着的白椭圆 + 椭圆里的大字 + 左上右下各一个
  小字。那个**斜椭圆**是 UNO 最好认的特征，缺了它就只是一堆彩色方块
- **不能出的牌保留全部颜色**。第一版用灰度滤镜压暗，结果出万能牌要选颜色时，
  根本看不出自己手里有哪些颜色 —— **颜色是这个游戏最核心的信息，任何时候都不能抹掉**。
  现在能不能出只靠"抬起来 + 发光"区分
- **点了出不了的牌会抖一下** + 轻提示音，而不是完全没反应（铁律：立即反馈）
- **摸牌堆画成一摞**（三层错开）+ 轮到你时浮一个大加号，才看得出"可以从这里拿一张"。
  第一版是一个纯色方块，没人看得出那是牌堆
- **对手手牌 = 一个牌堆 + 一个数字**（头像、牌堆、数字三件套）。中间试过铺开一排
  小牌背，牌一多就很乱，退回最简形式
- **每次出牌/抽牌都有一张牌飞过去**：出牌从出牌人飞向弃牌堆，抽牌从摸牌堆飞向抽牌人。
  不然孩子看不出"刚才是谁出了牌"、"我这张是哪来的"。牌桌上的数据其实已经更新了，
  飞过去的那张正好落在同一张牌上，所以看起来是连贯的
- **当前颜色做成弃牌堆外面的一圈**，外面再包一圈白边 —— 否则当前颜色和牌本身同色时
  这一圈等于看不见。万能牌改色后这里跟着变

> CSS 坑四则：飞牌的过渡必须**等两帧**再设目标位置（元素刚创建的那一帧改 transition
> 浏览器不会触发过渡）；`border-width` 不接受百分比（写了等于没写，要用 inset 阴影）；
> `container-type: size` 会把容器高度收成 0，导致 `cqmin` 算出来是 0、字号变成 0，
> 该用 `inline-size` 配合显式 `aspect-ratio`；**绝对定位元素的百分比 `padding`
> 按包含块算**，要按自身留边得用 `inset`（详见四子棋 5.2b）。

#### 教学引导（2026-09-23 新增）

**设计原则：情境教学，辅助逐渐撤掉** —— 不是"先上完课再玩"。

用户最初的方案是"进游戏时问要不要学，学一步问一次要不要继续"。改掉了两处：

- **不用"勾/叉"问她**。那要求孩子先理解"学习"这个抽象概念才能选。改成两张
  看得见的图：左边一只手指着牌（跟我学），右边牌桌加播放键（直接玩），
  配一句语音"要我教你玩吗"。她点哪个都看得懂自己选了什么。
- **不问"要不要继续学"**。每学完一条就弹窗问，孩子会被问烦，而且每次都要做一个
  她并不真正理解的决定。改成学完一条就**自然继续打这一局**，手指还在，
  遇到刚学的情况会再指一下。

#### 教学局是**写死的一副牌**（2026-09-24）

不靠运气让每一课出现，而是把牌发成固定的（`src/games/uno/tutorial.ts`）：

```
T1 娃 红3 盖红8   → 颜色一样可以出
T2 AI 红5
T3 娃 蓝5 盖红5   → 数字一样也可以出，颜色跟着变 → 剩一张，喊 UNO
T4 AI 蓝2
T5 娃 出不了 → 摸到蓝4  → 出不了就从这里摸一张
T6 AI 也出不了 → 摸牌   → 对方也没牌了，它的牌变多了
T7 娃 蓝4
T8 AI 蓝7
T9 娃 绿7（7 对 7）→ 牌出完 → 你赢了
```

关键性质：**孩子每回合恰好只有一张能出的牌，或者一张都出不了** —— 没有选择余地，
所以剧本不会被走偏。对手不需要脚本，正常 AI 在这副牌下每步也只有唯一解，
三种难度走法完全一样（有测试守着）。

#### 教学的讲述节奏（2026-09-24 第三版）

**开场只讲一句**（目标 + 牌放哪儿），规则全部留到每一回合当场讲：

| 时机 | 说什么 |
|---|---|
| 开场（指中间） | 我们轮流出牌，看谁先把手里的牌出完。出掉的牌就放在中间这里 |
| 第 1 回合 | 这张也是红色的，和中间的一样，点它就可以出 |
| 出牌之后 | 你出的牌放到这里了，接下来就要跟着它出 |
| 第 2 回合 | 数字一样，颜色不一样也可以出 |
| 出牌之后 | 现在最上面是这张牌了，所以能出的颜色也变了 |
| 第 3 回合 | 都出不了？那就从这里摸一张 |
| 对方摸牌时 | 它也没有能出的牌，也摸了一张，你看它的牌变多了 |
| 出完最后一张 | 牌都出完啦，你赢了！ |

三版的演变，结论是**开场越短越好，解释越贴近当下越好**：
1. 全程沉默，只在卡住时提示 → 孩子不知道自己在追求什么
2. 开场把三条规则一次讲完（约 15 秒）→ 听不进去，而且讲完就沉默
3. 开场一句讲目标，规则当场讲，**出牌之后还要讲"刚才发生了什么"** ——
   "牌放到这里了""颜色跟着变了"这类结果，孩子自己看不出来

功能牌（跳过/反转/+2）也走"出牌之后讲一句"这条路：第一次出现时解释效果。
教学那副牌里没有功能牌，所以这几句是在正常对局中触发的，只要教学总开关没关。

**谁出的都要讲** —— 对手先甩出一张轮空牌，孩子同样需要知道刚才发生了什么。
只有"你出的牌放这儿了""颜色变了"这类关于她自己操作的话，才限定她出牌时讲。

文案要讲清楚**完整效果**，不能只讲一半：

| 牌 | 说什么 | 为什么这么说 |
|---|---|---|
| 轮空 | 下一个人不能出牌了，他少了一次出牌的机会 | "轮空"这个词孩子不懂，要说成"少了一次机会" |
| +2 | 下一个人要摸两张牌，**而且这一轮不能出牌** | 官方规则是摸牌 **并** 跳过这一轮。只说"要摸两张"会让孩子以为他还能出 |
| 反转（3 人以上） | 出牌的顺序换方向了，现在反着轮 | |
| 反转（2 人） | 顺序换了方向。只有两个人的时候，对手就轮空，所以可以再出一张 | 两人局里反转等于轮空，效果完全不同，必须分开讲 |
| 万能牌 | 你随时可以出这张牌，出牌之后由你指定它变成什么颜色 | 讲在**选色弹层打开**的那一刻 |
| 万能+4 | …而且下一个人要摸四张牌，并且不能出牌 | 和 +2 一样，要连"不能出牌"一起讲 |

> **万能牌的讲解曾经永远触发不到**：它原本挂在教练逻辑里，只在教学模式生效，
> 而教学那副牌是纯数字的 —— 于是两边永远碰不到面（用户实测发现）。
> 现在它和其他功能牌一样走随堂讲解，只要教学总开关没关就生效。

#### 牌组构成（和官方一致，有测试守着）

每种颜色：**0 一张、1-9 各两张**、跳过/反转/+2 各两张；万能牌和万能+4 各四张。
L4 满配共 **108 张**，和实体 UNO 一样。所以"连着看到两张绿色的 3"是正常的。

摸牌堆摸完时，**把弃牌堆除顶牌之外洗回去**（官方规则），有测试守着"牌不会凭空消失"。
实际上很难摸完：L1 是 76 张，两人局只发 10 张。

#### 「要我教你吗」的触发条件

```
显示询问页 ⟺ 教学总开关是开的  且  教学局的三条规则没有全部学会
```

三条 = 同色可出、同数字可出、出不了就摸牌，各做对 3 次算学会。

**只看这三条**，因为教学那副牌是纯数字的，只会教到它们。原来把万能牌也算进来，
结果 L1 的孩子永远碰不到万能牌、永远凑不齐，进 UNO 会被无限次追问。
功能牌和万能牌走正常对局里的随堂讲解，不参与这个判定。

#### 关于「喊 UNO」

**去掉了。** 官方规则里它是**带罚则的义务**：打出倒数第二张牌时必须喊，
被抓到没喊要罚抽 2 张。对 5 岁孩子这只是"多一件会做错、会被罚的事"，
和"不做失败叙事"直接冲突。剩一张时的高亮也一并撤掉，免得暗示"这里该做点什么"。

- **不按课程表，只在她真的遇到那个情况时才教那一条**- **不按课程表，只在她真的遇到那个情况时才教那一条**。手里一张都出不了的那一刻，
  才教"从摸牌堆摸一张"
- **没讲过的规则优先于讲过但没学熟的**。第一版写反了 —— 只要"同色"还没学满 3 次
  就一直教同色，结果"数字一样也能出"从头到尾没讲过（用户实测才发现）
- 要讲的不只是"怎么出牌"，还有**孩子看不出来的结果**：出了同数字不同色的牌颜色会变、
  牌出完了就是赢了、对手还剩几张可以看这里 —— 这三条都是实测反馈补上的
- **第一次遇到某条规则：立刻讲 + 压暗周围**（聚光）。之后同一条规则不再主动打扰，
  只有她**卡住超过 5 秒**才轻轻指一下
- **同一条规则做对 3 次，提示就彻底消失**（`MASTERY`）。这是"可撤掉的脚手架"
  在教学上的同一个思路
- 四条规则（同色 / 同数字 / 出不了就摸牌 / 万能牌选色）全部掌握后，
  进游戏不再询问，直接开打
- 家长端有总开关和「重新开始教学」

判断逻辑在 `src/games/uno/coach.ts`，是纯函数、有 16 个测试；指示手指是
`src/components/PointingHand.vue`，跟随目标元素的实际位置，牌重排也不会指偏。

> 注意：我们的规则是**抽牌即结束回合**（官方规则），所以"摸到的牌正好能出"
> 这种情况在这个游戏里永远不会发生 —— 曾经为它写过一条提示，是死代码，已删。

#### 语音要【排队】，不能互相打断

一开始为了解决"首页念游戏名和进游戏那句叠在一起"，让新语音直接掐掉旧的。
重叠是没了，但变成了互相打断 —— 实测万能牌那句 7.67 秒的讲解**只播了 1.06 秒
就被下一句切掉**，孩子等于什么都没听到（用户反馈"万能牌没有语音"，查出来是这个）。

现在所有讲解走 `speakQueued()`：一句说完再说下一句。队列只留最近 3 条 ——
教学话术本来就稀疏，真堆积说明时机设计有问题，与其让孩子听一长串过期的话，
不如丢掉早的。换一局会清空队列。

**这类 bug 的共同点**：验证时只确认了"语音开始播"，没确认"播完"。
下次测语音，要测的是 `stop` 早于 `duration` 的次数。

#### 语音

`scripts/gen-voice.sh` 用 macOS 内置 TTS 生成，产物提交进仓库，运行时不做 TTS
（零延迟、离线可用、音色可控）。**中英韩三种语言各 18 句**，文本就写在脚本里的表格中，
改文本重跑即可，不用动代码。

- 嗓音：中文 Tingting、英文 Samantha、韩文 Yuna（都可用）。换音色

  没下载的会生成 0 秒空文件，脚本会检查并跳过那个语言
- **英韩文本是 AI 写的，没有母语者校对**，尤其"对 5 岁孩子说话"的语气。

- **只有中文语音进 PWA 预缓存**。三种语言全预缓存要 5.8MB，等于让所有人替

- **可出的牌自动高亮放大，不可出的牌灰掉且点不动**——默认**开启**，作用是让孩子在

#### AI

有概率放弃最优出牌（见 4.3）。功能牌越多，AI 的"次优"越容易被孩子察觉为"它好像也会犯错"。

**实测结论（2026-09-23，600 局，交换座位抵消先手优势）**：

| | 数值 |
|---|---|
| 认真档胜率 | 54.5% |
| 简单档胜率 | 46.7% |
| 光是先手优势 | 53.7% |

也就是说 **UNO 里难度对输赢只值 8 个百分点**，运气占绝对主导 —— 和翻牌配对完全不同

> 这时"随机选"和"选最优"是同一张，放弃最优也看不出来。

### 5.5 找相同（Dobble）—— 第四个游戏（2026-09-24）

规则一句话：**两张牌上永远恰好有一个相同的图案，找出来点它**。谁先点到谁得分，先到 5 分赢。

#### 为什么它适合这个年龄
不需要回合、不需要策略、不需要记忆 —— 只需要"看"。5 岁孩子在这件事上和大人差距最小，
是四个游戏里她**最可能真的赢**的一个。

#### 一台 iPad 两个人怎么玩
两张牌分别放在屏幕**上下两端**，对面那个人的整个半边（牌 + 比分）转 180°。
**各人点自己那张牌上的图案** —— 这样"谁先点的"根本不需要判定，
两个人的手不会抢同一块屏幕。和电脑玩时上面那张不转（没人坐那边，转过来反而难认）。

#### 牌是怎么造出来的
不是随机凑的，是**有限投影平面**：阶数 n 给出 n²+n+1 张牌、每张 n+1 个图案，
任意两张恰好共享一个。三档难度就是三个阶数：

| 档位 | 每张几个图案 | 牌数 |
|---|---|---|
| 2 阶 | 3 | 7 |
| 3 阶（默认） | 4 | 13 |
| 5 阶 | 6 | 31 |

> ⚠️ **阶数必须是质数**。n=4 时 mod 4 不构成域（2×2≡0），直线退化，
> 会出现共享**两个**图案的牌对 —— 孩子点了"对的"却被判错。有测试逐对检查 2/3/5 阶，
> 还有一条测试专门断言 4 阶是坏的，免得以后有人"顺手加一档"。

#### 界面上的几个决定
- **图案位置要抖动**（角度/半径/大小/旋转）。整整齐齐排一圈的话，孩子会靠"第几个位置"
  去比对，而不是真的在看图案。抖动值按【这张牌 + 第几个槽位】哈希算出来 ——
  同一张牌每次出现长得一模一样（可预期），不同的牌各不相同
- **点对了，两张牌上的那个图案一起亮**（绿圈 + 转正），让她看清"原来是同一个"
- **点错了只是灰一下 + 冻结 0.7 秒**，不扣分（铁律 4）。冻结是为了让"乱按"没有收益
- 比分画成 5 个点点，亮一个就是一分 —— 不认字也看得懂
- AI 的难度**只调反应时间**（简单档 3.8~6.5 秒），它永远找得到答案，只是慢；
  外加一定概率先点错一个，同样要吃冻结

## 6. 关键风险

| 风险 | 应对 |
|---|---|
| 做完孩子不爱玩 | 阶段 1 只做一个游戏就交给孩子实测，不要三个都做完才验证 |
| 动画/音效工作量被低估（这是儿童向体验的主体） | 阶段 0 就把音频与动画的基础设施搭好，不要当成最后的"美化" |
| 规则引擎和 UI 写在一起 | 见铁律 3；规则引擎必须先有单元测试才接 UI |
| iPad 真机手感与浏览器不一致（触控、横屏、音频解锁） | 每阶段末在真机上实测一次，不靠浏览器模拟下结论 |
| 过早为"微信联机"做设计妥协 | 联机只要求规则引擎纯函数化，其余一概不提前做 |
